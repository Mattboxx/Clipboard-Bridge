Clipboard Bridge / Apple and Android

Share your clipboard between Apple and Android devices

Mixed devices should not mean sending yourself an email just to move a link. Clipboard Bridge shares text, photos and files between iPhone, iPad, Mac, Android and Windows through a host on your own network.

On iPhone, Send and Receive can live in Control Center. The Send Shortcut can also appear in the Share Sheet, next to the sharing options in your other apps. Android has its own app and Share target.

First, choose where the shared clipboard lives

Apple and Android clients connect to the same host. The mobile apps do not host a direct phone-to-phone service. Choose one of these two options:

  • Already have a Windows PC? Install Clipboard Bridge and choose Settings > General > Server mode. Keep the PC and app running. There is no separate server to install and no web page in this mode.
  • Want an always-on clipboard? Run the Docker/Python server on a home server, NAS or Raspberry Pi. It adds browser access and optional separate accounts, and keeps working while Windows is off.

Copy the chosen host's network address. Use it in every client and Shortcut. You do not need a Clipboard Bridge online account or a project-operated cloud service.

If your main pair is Windows and iPhone, use the shorter Windows to iPhone clipboard guide.

Share menu, Home Screen and other useful tips
Send without copying first
In the Send Shortcut's details, enable Show in Share Sheet. Then select a photo, file or link in another app and use Share > Load Clipboard. The Shortcut must use Shortcut Input when present: follow the input and multi-file recipe. Apple's Share Sheet guide.
Prefer an icon on your Home Screen?
Open the Shortcut's details and choose Add to Home Screen. Repeat for Receive. Apple's Home Screen guide.
Cannot find the Shortcut?
Import and configure it first. Control Center uses the Shortcut control, not a separate Clipboard Bridge app control. In Share, scroll down; if the action is missing, check Show in Share Sheet and the accepted input types.
Test once before using it every day
Keep the host awake and use the same trusted network or private VPN. Send a short message and receive it on the other device. Allow local-network access if iOS asks.
  1. On Android 10 or newer, install the Clipboard Bridge APK. Enter the chosen host's address in Settings and save. Android support is currently a public beta.
  2. On iPhone or iPad, import the two iPhone Shortcuts. Set Load Clipboard to POST to /clipboard and Download Clipboard to GET /clipboard/latest/raw, using the same host.
  3. Add both Shortcuts to Control Center > + > Add a Control > Shortcut > Choose on supported iOS versions. Enable Show in Share Sheet for Send, and configure Shortcut Input using the Share Sheet recipe.
  4. To send from iPhone, copy text and tap Load Clipboard in Control Center, or send a photo/document from Share. On Android, tap Receive latest, then paste the text or open the received file.
  5. To send from Android, copy text and use Send clipboard in the app. On iPhone, tap Download Clipboard, then paste into the destination app.
Send:    POST http://YOUR_HOST:5088/clipboard
Receive: GET  http://YOUR_HOST:5088/clipboard/latest/raw

Replace YOUR_HOST with the Windows or standalone server address, not the phone's own address. One pair of actions covers the latest content; you do not choose a different endpoint for a newer photo versus newer text.

Share a clipboard between Mac and Android

There is no native Mac client. On macOS, build the same user-triggered workflow in Apple's Shortcuts app and connect it to your Windows or standalone host.

  1. Create a Send Shortcut: get the clipboard, then use Get Contents of URL with POST to http://YOUR_HOST:5088/clipboard. Use the copied text as the request body for a basic text-only setup.
  2. Create a Receive Shortcut: GET http://YOUR_HOST:5088/clipboard/latest/raw, then Copy to Clipboard.
  3. Copy a short sample message on Mac, run Send, and receive it in the Android app. For the other direction, send on Android and run Receive on Mac.

Use the Mac setup guide for action details and permissions. The distributed signed iPhone exports have not been physically tested on Mac; create or adapt the actions rather than assuming a native Mac installation. File and group handling requires the additional recipe below.

This is an independent workflow for mixed-device households, not Apple's built-in Universal Clipboard. It does not require Android to join Handoff or use your Apple Account.

Move photos, PDFs and other files too

On Android, choose Clipboard Bridge from another app's Share menu. On iPhone, use the Send Shortcut in the Share Sheet. The source app must provide access to the item, and the Shortcut must pass that input to the host.

A selection of several files can become one server history entry. The advanced Apple Shortcut recipe sends a temporary ZIP to /clipboard/bundle and can extract the latest group after checking /clipboard/latest/meta. The signed downloads have not been changed to include every advanced recipe.

Original file contents are preserved. Copied formatted text is received as plain Unicode text, with emoji, accents and line breaks. The newest upload always becomes the latest item; an older file does not take priority over newer text.

The Android history reads the selected host and account, rather than keeping an unrelated local-only list. You can restore an earlier item or delete an individual history entry.

What is automatic, and what needs a tap?

  • iPhone and iPad: run Send or Receive from Control Center, or Send from Share. There is no continuous background iOS clipboard watcher.
  • Mac: run the manual Shortcuts. There is no native Mac client or continuous Mac clipboard synchronization in this project.
  • Android: incoming notifications, receiving options and Quick Settings actions are available. Android restricts background clipboard reading, so copying inside another app is not guaranteed to trigger an upload.
  • Windows: optional automatic sending and receiving run while the app is active. Notification types and hotkeys can be configured in Settings.

Start with one manual text transfer in each direction. Enable optional automation afterwards. Physical phone, Mac and VPN acceptance tests are not implied by the automated API and build checks.

Use your local network, or a private VPN

All clients must reach the same host. A trusted home Wi-Fi/LAN is enough; guest Wi-Fi may isolate devices. Away from home or on untrusted Wi-Fi, we recommend Tailscale. Connect your devices and host to the same private Tailscale network, then use the host's Tailscale address in every app and Shortcut. This also works when Windows itself is the host. Tailscale is optional; another private VPN can work too.

If an always-on server provides a separately configured subnet route, clients can keep using the same LAN address outside the house. See the VPN and subnet-routing guide.

Accounts and tokens are optional. Without a username, clients use the general shared clipboard. Named accounts on the standalone server have separate histories; select the same account in Android Settings and both Apple URLs. See account URL examples.

Keep the host private. Do not forward port 5088 to the Internet. Credentials in account/token URLs are readable, and plain HTTP does not encrypt them or the clipboard data. This project does not replace network security.

Check the connection before changing the Shortcuts

If you see different histories, compare the full host address and selected account on every device. If a request times out, check that the host is awake, the firewall allows your private network and VPN routes are available. A missing web page is normal in Windows Server mode.
